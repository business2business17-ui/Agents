# Amazon Market Intelligence Agent — расчётное ядро

Эталонная реализация детерминированного ядра агента по ТЗ v1.2. Код закрывает главные проблемы из [анализа v1.1](Анализ_ТЗ_v1.1_проблемы.md). Язык — Python ≥ 3.10, только стандартная библиотека; для тестов нужен `pytest`.

LLM в ядре не используется. Всё, что здесь считается, — это инструменты, которые вызывает LLM-оркестратор (ТЗ §20.1). Сам оркестратор и коннекторы импорта (Helium 10 / SmartScout / Keepa) в этот пакет не входят.

## Как главные проблемы решены в коде

| Проблема (анализ v1.1) | Решение | Модуль | Тесты |
|---|---|---|---|
| **P1/P2** Нет алгоритма решения, HOLD не определён, нет критичных полей | Правила R0–R5 по порядку, ограничения (LOW → не выше TEST, ASSUMED_COGS, сезонная аномалия, resale-риски), `decision_trace`, условное решение «после устранения» | `mia/decision.py`, `pipeline.critical_missing` | `test_decision.py` — каждое правило |
| **P3** Две конкурирующие системы ранжирования, Score невычислим | Score только про привлекательность, полосы нормализации в конфиге, без «качества данных»; Confidence отдельно, по слабому звену | `mia/score.py`, `mia/confidence.py` | `test_compliance_confidence_score.py` |
| **P4** Нет модели resale | Buy Box Engine: `N_competitive`, доля Buy Box low/base/high, hard stops (доминирование Amazon, цена ниже MVP), REVIEW (нет авторизации), ограничения (IP-жалобы) | `mia/buybox.py` | `test_market_engines.py`, `test_pipeline.py` |
| **P5** Contestable Market без формулы | `min(спрос, бюджет, запас, эмпирика когорт)` + binding constraint; дедупликация ключей; когорты с порогами 10/20 ASIN | `mia/contestable.py` | `test_market_engines.py` |
| **P6** Неоднозначные финансовые формулы | Налоговая база (EU с НДС / US без), referral от gross, тарифы whole/marginal, pre/post-ad, BE ACoS net и console, break-even units, минимально жизнеспособная цена | `mia/economics.py` | `test_economics.py` — golden-расчёты |
| **P7** Нет cash-flow | Помесячная модель: депозит/остаток поставщику, lead time, задержка выплат Amazon, дозаказы по ROP, stockouts, Required Capital, payback, 5 стресс-тестов, E[Profit], Capital at Risk | `mia/cashflow.py` | `test_cashflow.py` — ручной расчёт |
| **P8** LLM может выдумать число | Реестр метрик + плейсхолдеры `{{metric:id}}` + валидатор + перегенерация с обратной связью + удаление непрошедших предложений | `mia/grounding.py` | `test_grounding.py` |
| **P15** Compliance без EPR / VAT / косметики | Data-driven чек-лист по рынку, категории и модели; PASS без evidence не принимается; неустранимый BLOCKED → R1 | `mia/compliance.py` | `test_compliance_confidence_score.py` |
| Отчёт ES: словесные сравнения противоречат таблице («вдвое больше», «без мидии», «единственный»), модели не из сегмента или наши же гипотезы | Таблица фактов конкурентов; сравнения, место, состав и количество — только плейсхолдерами `{{cmp\|rank\|ing\|count:…}}`, фразу считает код; проверка моделей в карточках продукта | `mia/factcheck.py`, `grounding.validate(..., facts)` | `test_factcheck.py` |
| Нет импорта выгрузок, экономика гипотез не считалась | Чтение Helium 10 Xray/Cerebro (xlsx/csv, без зависимостей); контроль качества (битая цена → выручка/шт.); определение ниши (include/exclude/цена/ручные исключения); метрики ниши, CR/HHI, Amazon Retail, когорта; бейдж Amazon «X+ bought» как второй источник оценки; FBA fee из Fees − referral; кластеры ключей; прогон каждой гипотезы через Decision Engine | `mia/importers/`, `mia/niche.py`, `mia/xray_run.py` | `test_importers_niche.py` |
| Решение на стр. 29–31 из 31, числа без источника, повторяющиеся карточки | Отчёт HTML/PDF: на первой странице решение, Score, уверенность и слабое звено, волна 1 портфеля, главные риски, следующие шаги; далее гипотезы, портфель, подниши, карточки с проверками доказательности, конкуренты, чего не хватает, приложение с metric_id и журналом валидатора. Текст — только через плейсхолдеры, LLM-текст проходит grounding + factcheck; PDF печатает headless Edge/Chrome | `mia/report.py` | `test_report.py` |
| 14 SKU «в волну 1» по одному порогу >100 продаж, без капитала и каннибализации | Правила доказательности: ≥ 2 бренда-модели, хотя бы одна молодая модель, цена в коридоре моделей ± 25 %, спрос не держится на одном ASIN, продажи моделей зажаты бейджем Amazon; статусы validated / weak / hypothesis / white_space. Портфель: волна 1 = GO/TEST + validated, жадный отбор по E[Profit]/капитал в пределах бюджета и FBA capacity, без цели — один SKU; каннибализация по общим ключам и ASIN; риск MOQ; план «после устранения» | `mia/evidence.py`, `mia/portfolio.py` | `test_evidence_portfolio.py` |
| Агент заточен под одну категорию | Профили категорий: автоопределение по колонке Category (RU/EN/DE/FR/IT/ES), стартовый referral с пометкой «не сверено», compliance для игрушек, детских товаров, электроники, контакта с пищей, продуктов и добавок, текстиля; стоп-листы claims для кормов, косметики и продуктов; единицы US (фунты/дюймы); скрининг папки выгрузок с поиском дублей | `mia/categories.py`, `mia/compliance.py`, `mia/claims.py`, `mia/scan.py` | `test_categories.py` |
| Отчёт ES: «противовоспалительный» на всех карточках | Правила для кормов EU (FBO 183/2005, 68/2013 и 1831/2003, маркировка 767/2009, dietetic feed 2020/354; GPSR не применяется) + стоп-лист claims RU/EN/ES/DE/FR/IT: запрещённое → BLOCKED (устранимо, R3), «разработано ветеринарами» → REVIEW | `mia/claims.py`, `mia/compliance.py` | `test_claims.py` |

## Запуск

```bash
python -m pytest -q
```

```bash
python examples/run_example.py examples/de_private_label_skincare.json
```

```bash
python examples/run_example.py examples/de_resale_fragrance.json
```

```bash
python examples/run_xray.py examples/de_tanning_xray.json --pdf
```

```bash
python examples/scan_xray.py XRAY
```

Скрининг всех выгрузок Xray в папке: размер, концентрация, барьер отзывов, доля Amazon, доля новых ASIN, согласие оценок Helium с бейджем Amazon, качество данных и дубли. Решений не выносит — это отбор ниш.

Последний пример берёт реальные выгрузки из `XRAY/` (DE, масла и ускорители загара) и прогоняет нишу и продуктовые гипотезы, собирает портфель и пишет отчёт `*.report.html` (с `--pdf` — ещё и PDF через Edge/Chrome). Параметры, которых нет в выгрузках (COGS, CPC, доля клика нового бренда, бюджет, lead time), в конфиге — предположения.

Пример печатает карточку решения и нарратив, а рядом с входным файлом сохраняет полный `*.decision_package.json` (контракт ТЗ §22.3).

**Входные данные в `examples/` — иллюстративные.** Ставки комиссий, НДС, CPC и продажи — примеры для проверки расчётов. Это не данные реальной ниши. Перед реальным анализом ставки берутся из актуальной fee schedule и таблицы `vat_rates`.

## Результаты на примерах

| Пример | Решение | Почему |
|---|---|---|
| DE, private label, сыворотка | **HOLD (R5c)**, Score 54,8 | Стоимость заказа через PPC (CPC / CVR ≈ €9) выше pre-ad contribution (≈ €5,9), поэтому компонент PPC = 0. Доступно ≈ 65 шт./мес. при MOQ 500, окупаемости на горизонте 18 мес. нет |
| DE, resale, парфюм | **HOLD (R3)**, после устранения — HOLD (R5c) | Hazmat review не подтверждён. Даже после него маржа ≈ 1,8 % при 3 конкурентных офферах (доля Buy Box ≈ 25 %) |
| Тест: сильная ниша | **GO (R5a)** | Дешёвый трафик, сильная когорта новых входов, 3 закрываемых pain points → Score ≥ 80 |

## Конфигурация

Все пороги (полосы Score, кривые разгона, веса сценариев, стресс-параметры, пороги confidence) собраны в `mia/config.py` → `Config` с `version`. Это стартовые значения для калибровки (ТЗ, «Соглашение о порогах»). Изменение конфигурации не требует правки кода, а версия попадает в каждый Decision Package.

## Известные упрощения

- Шаг модели — 30 дней. Продажи партии начинаются с первого полного месяца после поступления.
- Стартовая партия рассчитывается по Base и одинакова во всех сценариях.
- Неликвидная часть возвратов учтена в прибыли, но не уменьшает складской остаток.
- `P(target)` и Monte Carlo (Phase 2) не реализованы. Достижимость цели видна по сценариям.
- Импорт: только Helium 10 Xray и Cerebro. Keepa (сезонность, тренд 12 мес., выбывшие ASIN), CPC из Ads и LLM-классификация релевантности (§3.1 п.3) не подключены; когорта новых ASIN — только выжившие в выгрузке.
- Нет анализа отзывов и XLSX/PDF-отчётов: это следующие этапы MVP.
